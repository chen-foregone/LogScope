# 08: 限制单轮总时限并协调终态竞争
Status: needs-info
Type: task
Blocked by: 06, 07

## What to build
纵向交付持久总预算与退出协调 schema、受控期限/结束 API、原子终态裁决及 UI。总时限包含查询、重试和等待，执行安全确认未完成时不提前释放名额。

## Blocked by
- 06 处理查询故障、有限重试及部分来源缺失
- 07 取消调查并隔离迟到产物

## Spec
[首版实施规格](../spec.md)：D2、D3、D8。
用户故事主要交付：US-09；US-47 期限与终态竞争部分，关联 US-11、US-18。
验收组主要交付：A09；A15 取消/超时/完成部分，失联交错10补全；A26 终态变化。

## 开工门槛
退出协调协议必须明确：停止安排、隔离确认、原子裁决事件与合法结果、名额释放及可观察验证方式。当前未选机制，needs-info 待具体设计契约齐备解除。未批准取消总优先或超时总优先，不硬编优先级；若设计改变既定终态业务含义才需另行确认。例行协调算法可在授权内设计。

## 验收标准
- [ ] 从单轮启动起总时限10分钟，包含原始查询、最多额外2次重试及2秒/5秒等待和其他等待，不因重试刷新预算。
- [ ] 达到时限停止安排新操作并走失败处理；不再为已耗尽预算的新查询启动完整30秒等待。
- [ ] 旧执行停止或隔离尚未确认时仍保持未安全结束的可见阶段、占名额且不可重开；不能用到时限猜测旧执行已停止。
- [ ] 对按明示裁决协议归属超时退出的轮次，安全确认后原子落定失败与超时原因；已合法结束的轮次不被超时覆盖，持久保存既有证据，名额只释放一次。
- [ ] 控制完成、取消与超时在提交前后交错，最终只有一个符合明示协议的合法终态，无双释放、双执行或迟到证据/结论/等级写入。
- [ ] UI/API 可理解地显示退出等待和最终原因，业务状态变化更新最后更新时间；刷新不改变裁决结果。
- [ ] 不把正常证据不足变成失败；失联事件交错由10纳入相同裁决协议，不以任意优先级替代业务约束。

## 测试与完成证据
HTTP API + 真实 PostgreSQL，配可控时钟、调度、查询与确认适配点，保存10分钟边界、等待预算、隔离未确认和交错事件外部轨迹、状态和UI证据。不得仅测内部计时函数；10补A15失联矩阵，19验证实际执行身份。完成贯通 schema/API/UI 与竞争测试。
