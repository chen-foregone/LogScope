# 12: 引用历史证据并保持跨轮一致性
Status: ready-for-agent
Type: task
Blocked by: 04, 09

## What to build
纵向交付证据与本轮纳入关系的 schema/迁移、历史引用API、来源轮与核验状态UI；引用不改历史，脱敏代号在同调查跨轮保持一致。

## Blocked by
- 04 可靠判同并展示本轮证据条数
- 09 手动重开调查并查看逐轮历史

## Spec
[首版实施规格](../spec.md)：D4、D8。
用户故事主要交付：US-22 的跨轮部分、US-25、US-26；关联 US-15、US-21。
验收组主要交付：A20、A17 的跨轮最终补全；A18 并发纳入回归、A26 证据变化部分。

## 开工门槛
无额外未知输入，遵守04、09依赖；引用关系与一致代号算法可在授权内设计，不保存原敏感值。来源不可访问与核验失效的完整区分由13补全，本单必须已有明确可核验材料检查。

## 验收标准
- [ ] 历史证据默认不继承，显式纳入前检查本轮服务、固定日志范围与仍可核验性；不符合条件拒绝并显示原因。
- [ ] 纳入后显示来源轮次和核验材料，原轮归属、证据与历史计数不变，引用不表示本轮覆盖完整。
- [ ] 同一证据在本轮重复或并发引用只计一次，新获取与历史引用可靠判同后不双计；仅历史独存不计本轮。
- [ ] 调整服务或范围后的新轮不得把上一轮覆盖自动当作新范围覆盖，不借引用绕过服务/时间检查。
- [ ] 同调查跨日志跨轮同身份代号一致，不同调查独立；凭据直接屏蔽、敏感关联标识处理，数据库及错误输出无原值。
- [ ] 引用绑定调查、目标轮和有效写入阶段，已结束或隔离的执行不能迟到纳入；不通过引用覆盖历史。
- [ ] UI/API显示本轮真实条数与来源轮，实际新增纳入更新最后更新时间，重复无变化或读取不更新，刷新后关系与代号不变。

## 测试与完成证据
HTTP API + 真实 PostgreSQL 覆盖跨轮同身份、跨调查、范围/服务不匹配、不可核验、并发重复及新旧同源记录；提供脱敏存储检查与UI历史引用证据。替身仅安排外部材料，真实来源与Agent仍由18、19验证。A17跨轮与A20由本单明确收口，不留给20补遗漏。
