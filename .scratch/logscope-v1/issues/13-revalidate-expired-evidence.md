# 13: 处理证据失效并完成新轮重新核验
Status: ready-for-agent
Type: task
Blocked by: 05, 12

## What to build
纵向交付来源可访问性、证据可核验性和结论版本变化 schema、核验读取与手动新轮API、详情UI。证据源不可访问不自动等于证据不可核验，重新核验保持只读。

## Blocked by
- 05 形成可追溯结论并结束调查
- 12 引用历史证据并保持跨轮一致性

## Spec
[首版实施规格](../spec.md)：D4、D5、D8。
用户故事主要交付：US-27、US-30、US-31。
验收组主要交付：A21、A23；A22 因果充分性回归、A26 结论核验变化。

## 开工门槛
无额外未知输入，遵守05、12依赖。核验判据与结论变更版本可在授权内设计；真实来源与模型能力在18、19验收。不增加强制确认根因或自动新轮旁路。

## 验收标准
- [ ] 来源不可访问但保留可核验脱敏片段及来源信息时继续保留证据并标注来源不可访问，不一概判不可核验。
- [ ] 只有失效链接且无核验材料时标不可核验，不再作为确认根因的充分依据，状态及原因持久可追溯。
- [ ] 关键证据不可核验且无其他充分支撑时当前结论变待重新核验；有其他充分支撑时不机械降格。
- [ ] 保留原结论与变更历史，不宣称原结论错误，不修改已结束轮次状态、不自动重开；核验状态与严重程度独立。
- [ ] 用户通过标准启动契约手动新轮，仍受服务范围、唯一轮与实例容量约束，不允许任意强制确认。
- [ ] 新轮仅做只读核验，有充分可核验因果链才恢复确认并留历史；仅新增数量/时间相关材料或仍有关键缺口不得恢复。
- [ ] UI/API展示来源状态、核验状态、依据和逐次变化；结论业务变化更新最后更新时间，查看不更新，重启后历史保持。

## 测试与完成证据
HTTP API + 真实 PostgreSQL 配可控来源可访问性，逐案验证有片段/仅链接、关键/非关键失效、充分替代支撑、手动新轮充分与不足恢复；提交语义判断、历史和UI证据。受控案例不证明真实模型质量，19用真实Agent补足。完成包含 schema/API/UI 及A21/A23全部局部验收。
