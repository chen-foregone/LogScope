## 开工门槛
须明确延期输入是新到期时间还是延长长度、校验方式、允许上限及过时请求处理契约；当前未选，needs-info 待具体契约齐备解除。没有已批准默认延期天数，不能自行补默认值；不推翻30天和7天规则，普通版本/幂等算法可在授权内设计。

## 验收标准
- [ ] 无轮待处理从创建时间起保留30天；有轮按最近一轮结束时间+30天计算，所有结束状态均按该轮实际结束时间。
- [ ] 新轮启动重新计算周期，运行中不执行清理；结束后按新轮结束时间重算，不沿用旧轮已到期期限误清理。
- [ ] UI/API显示保留期限与当前保留阶段，到期前7天提示可延期；仅查看、刷新、搜索不延长保留期。
- [ ] 到期只标记待用户确认清理，不静默永久删除，详情仍可查看实际可保留材料。
- [ ] 延期按明示输入/校验/上限契约生效，无未经批准的默认延期天数；错误或过时请求不悄悄延长。
- [ ] 延期请求重放不重复叠加，延期与新轮启动、清理竞争按版本与事务重核，不允许过时操作清掉正在运行调查。
- [ ] 保留和延期事实持久化，刷新重启一致；UI清楚告知实际新期限，保留变更更新时间契约明确而读取无变化。

## 测试与完成证据
HTTP API + 真实 PostgreSQL 配可控时钟验证创建/最近结束+30天、前7天边界、新轮重算、运行保护、查看不延期及延期重放/冲突。提供时间输入输出、持久化和UI证据；17补清理竞争最终验收。完成贯通 schema/API/UI，不以单独计时函数测试替代业务API。
