## 开工门槛
须选定提供方、模型及真实调用协议，具备受控访问授权和安全凭据注入；明确允许工具、输出校验、执行身份传递、终止确认和旧写入隔离的实际接入契约。当前选择与访问条件未齐，needs-info 待具体契约和访问齐备解除，不虚构供应商或执行框架已批准。凭据不进工单、记忆和验收报告。

## 验收标准
- [ ] 通过真实Agent接口及18真实来源完成实际分析调用，配置/凭据经安全渠道注入，输入只含前置脱敏材料，错误和产物无秘密原值。
- [ ] 工具仅可只读查询被调查环境，范围受固化服务时间及有效identity控制；拒绝修复、重启、配置写入、删除日志与任意自由执行工具。
- [ ] 产物可追溯到证据：确认须说明现象、因果机制、关联证据、关键矛盾及替代解释；仅数量/时间相关不确认，不强制两条证据。
- [ ] 不足时输出待验证假设、依据和缺口，正常结束为已完成／未确定根因；通过案例语义审查而非仅结构验证评价真实输出。
- [ ] 关键证据失效后按13呈现待重新核验，手动新轮只读获取充分因果证据才恢复，保留历史，不自动续跑或重开。
- [ ] Agent等级依据按业务影响展示，人工等级不能覆盖；新建议需用户确认，过时确认拒绝，跨轮保留人工时间与非当前验证提示。
- [ ] 实际执行取消/超时/失联时停止安排，未安全确认不释放名额；旧执行迟到证据、结论、等级全拒绝，实例最多3调查且不排队。
- [ ] schema持久产物、真实API与UI一致，刷新重启后可追溯；业务变化更新时间，读取不变，建议绝不自动执行修复。

## 测试与完成证据
以 HTTP API + 真实 PostgreSQL、真实Agent与真实来源验证选定代表案例，提供脱敏调用记录、工具权限、语义评审、证据链、人工确认UI及实际执行隔离证据。故障可控适配测试需标明替身范围；假Agent不能冒充A34，有限真实案例不宣称普遍模型质量保证。完成贯通 schema/API/UI 和安全集成。
