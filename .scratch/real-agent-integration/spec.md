# 真实百炼 Agent 与模拟日志来源的受控分析闭环

Status: ready-for-agent
Parent: [19：接通真实Agent并验证受控分析闭环](../logscope-v1/issues/19-connect-real-agent-and-analysis-loop.md)

## Problem Statement

目前调查能保存受控证据和模板结论，但启动调查不会自动调用真实模型。用户需要在 Windows 本机通过真实模型分析模拟日志，查看可追溯的假设、结论和业务影响建议，同时保留人工决策及可靠的停止边界。

工单 18 实际交付的是模拟 HTTP 来源。本规格限定为真实百炼模型与该模拟来源联调，不代表真实日志来源接入完成，也不能据此勾选 A33 或完整 A34。

## Solution

采用单个只读调查 Agent：LangChain 接入百炼 qwen-plus，LangGraph 显式编排分析、白名单工具调用、校验与结束。现有后端和 PostgreSQL 继续裁决调查状态、执行身份、范围、并发名额、产物有效性和人工严重程度。

用户手动启动调查后，本机受控 worker 获取模拟日志的脱敏材料并调用真实模型；模型可在预算内按证据缺口补查。页面展示已保存结果及执行状态，不直接展示未经校验的模型流式文本，不执行自动修复。

## User Stories

1. 作为调查用户，我希望手动启动真实模型分析，以便从已登记问题进入实际排查。
2. 作为调查用户，我希望页面明确标识模拟日志来源，以免误认为已完成生产来源验收。
3. 作为调查用户，我希望模型只读取本轮固化服务和时间范围，以免扩大调查范围。
4. 作为调查用户，我希望根据证据缺口补查日志，以便形成多轮但有界的分析。
5. 作为调查用户，我希望每个判断关联已纳入证据，以便核查依据。
6. 作为调查用户，我希望获得多种故障类型的分析，以免仅能处理依赖错误传播。
7. 作为调查用户，我希望证据不足时看到待验证假设、依据和缺口，以免推测被当成已确认根因。
8. 作为调查用户，我希望看到因果机制、替代解释和关键矛盾，以便判断分析是否可信。
9. 作为调查用户，我希望未确定根因也能正常结束调查，以免证据不足被误标为技术失败。
10. 作为调查用户，我希望证据失效后呈现待重新核验，以便保留原结论的历史含义。
11. 作为调查用户，我希望手动启动新轮核验，以免系统自动续跑或重开调查。
12. 作为调查用户，我希望获得业务影响依据和严重程度建议，以便作出人工判断。
13. 作为调查用户，我希望人工等级不被模型覆盖，以便保留决策权。
14. 作为调查用户，我希望过时建议不能被确认，以免覆盖新决策。
15. 作为调查用户，我希望取消后不再安排新动作，以便可靠停止排查。
16. 作为调查用户，我希望失联时看到正在确认执行状态，以免误以为执行已安全退出。
17. 作为调查用户，我希望旧执行的迟到产物被拒绝，以免污染新轮分析。
18. 作为调查用户，我希望刷新和重启后仍能追溯已保存产物，以便复核过程。
19. 作为本机操作者，我希望重启不自动恢复旧图，以免绕过执行授权。
20. 作为本机操作者，我希望凭据和未脱敏材料不出现在日志、checkpoint 或报告中，以便保护秘密。
21. 作为本机操作者，我希望本次联调累计预算为人民币 10 元，以便控制真实模型成本。
22. 作为本机操作者，我希望并发调用先预留费用，以免多个调查重复使用同一余额。
23. 作为本机操作者，我希望调用结果不明时保守记账，以免重复调用和低估费用。
24. 作为维护者，我希望旧协议及历史展示继续可用，以便渐进接入真实模型。
25. 作为维护者，我希望确定性回归主要使用模型替身，以便重复验证而不耗尽真实调用预算。
26. 作为验收人员，我希望真实调用和替身测试分别记录，以免结构通过被当成模型质量保证。

## Implementation Decisions

- 运行环境为 Windows 本机，单 Agent；一个图节点是执行步骤，不要求每个节点都是 Agent。
- 默认模型为百炼 qwen-plus；通过 ChatOpenAI 使用百炼 OpenAI 兼容 Chat Completions 和工具调用。不使用 Responses API，不自动切换模型。
- 密钥通过服务端 DASHSCOPE_API_KEY 注入，百炼凭据与执行器凭据分离。调用前确认端点地域与密钥匹配；缺少凭据时真实调用保持关闭，不索取或保存密钥原值。
- 新增依赖限定为必要的 LangChain 模型接入、LangGraph 及传递依赖，实施时固定验证过的兼容版本。支持的模型显式关闭 thinking；温度不构成正确性保证。
- LangGraph 管流程，现有业务状态为权威。采用事务内接纳、提交后受控领取；外部模型请求不占用长数据库事务。
- 工具仅可查询固化范围和读取本轮已纳入证据。身份由服务端绑定；拒绝任意 HTTP、SQL、Shell、修复、重启、配置写入和删除日志。
- 在模型请求前、工具执行前、产物保存前重新检查执行身份、停止请求、截止时间及预算；历史证据不自动纳入本轮。
- 保留现有最多三调查、不排队和单调查活动轮次约束。取消、超时、失联未安全确认前不得释放名额。不能把关闭模型连接视为所有执行已终止。
- 日志和问题描述均为不可信输入；先脱敏再提供给模型。自由文本产物保存前也须校验、脱敏，无法可靠处理时拒绝。错误不回显原始供应商响应或秘密。
- 扩展版本化分析协议，与旧受控协议共存。包含结论类型、故障分类、现象、机制解释、证据引用、替代解释、关键矛盾、证据缺口、只读建议、期望版本和结束标记；限制字段长度、数组数量和请求体大小。
- 分类覆盖依赖、资源、配置、权限、应用错误及未知。模型自报 confirmed 不构成确认；尚无充分可核验支撑的类别保存为待验证假设，不能仅凭结构完整、数量或时间相关确认。
- 保存前检查引用属于本轮且符合有效性要求。新增类型不得破坏已有因果支撑、待重新核验和手动新轮恢复规则。
- 严重程度依据业务影响，不代表根因可信度。复用现有建议、人工确认、版本和幂等规则；人工等级不被覆盖，跨轮保留人工时间及非当前验证提示。
- 优先复用现有启动、查询、结论、等级、取消及详情 API；内部 worker 调用业务能力，不新增绕过权限的万能 Agent 接口。工具调用协议与业务 API 显式转换。
- 错误区分格式错误 422、未认证 401、失效执行或越界 403、资源不存在 404、版本或状态冲突 409、基础设施不可用 503。写操作保留幂等身份，同身份不同内容拒绝。
- 增加运行、调用记账、预算及脱敏 checkpoint 持久化。运行关联唯一执行身份；调用序号在运行内唯一；checkpoint 步骤有序且版本化；审计时间不因读取改变。
- checkpoint 仅记录脱敏状态和引用，不保存密钥、未脱敏日志或完整思维链。不启用外部 tracing 数据上传，不授权取消、超时、失联或重启后的旧执行自动恢复。
- 预算按本次开发联调累计 10 元，不是每轮 10 元。金额用固定精度整数；并发事务预留输入和最大输出费用，成功按用量结算，结果不明保留预留。默认禁用隐式模型重试；余额不足不发新请求。
- 调用前核对价格、最大输出及计费用量覆盖，记录价格版本；无法保守估价时不得真实调用。供应商账单为准，本地估算不冒充账号硬限额；账号侧限额和告警如可用则配合配置。
- UI 保留模拟来源标识，展示运行阶段、模型、调用次数、估算费用、退出原因及已校验产物。详情适度拆分，列表沿用现有组件、URL 状态和请求竞态保护，不新增全局 Store。
- 保持受控本机部署，不宣称已有多用户登录、RBAC 或组织数据隔离。执行凭据不能代替用户权限体系。
- 数据迁移采用增量扩展，不覆盖历史产物；实施前重新核对编号，避免与并行归档迁移冲突。回滚先停执行并禁用真实调用，保留必要脱敏审计记录。

## Testing Decisions

- 已由用户确认：以 HTTP API、真实 PostgreSQL 和浏览器 UI 为主要测试边界，测试外部行为，不绑定节点名称、内部调用顺序或框架私有结构。
- 参考已有查询、结论、取消、失联、严重程度及来源 UI 测试，复用数据库隔离、可控时间与调度设施。
- 可控模型替身覆盖多轮工具、非法 JSON、编造证据、提示注入、材料超限、超时、取消、失联、迟到写入、结果不明和预算并发；报告明确替身范围。
- 模型适配层补协议测试，验证请求参数、tool_calls、错误脱敏及 token usage 映射；不以兼容接口名称推定全功能兼容。
- 数据库测试验证外键、唯一约束、费用非负和三调查竞争预算。新旧分析协议及历史记录均回归。
- 浏览器测试验证运行、加载、空数据、失败、证据跳转、更多故障假设、人工确认、过时建议和刷新后的产物一致性。
- 真实百炼代表案例仅在配置与授权就绪后、累计预算内运行，覆盖有依据、证据不足与矛盾场景，保存脱敏调用及人工语义评审。不得伪造真实调用成功或普遍模型质量保证。
- 分批先写行为测试，再实施最小变更；经常运行单文件测试和类型检查，最终运行完整套件并进行代码审查，只提交本次变更。

## Out of Scope

- 真实日志供应商接入及 A33、完整 A34 验收。
- 自动修复、任意执行、多 Agent、跨调查记忆和自动模型切换。
- 自动恢复旧执行、云端部署和 Linux 执行终止适配。
- 登录、RBAC、多租户及无关归档功能改造。
- 全面重写现有后端分层或前端状态管理。
