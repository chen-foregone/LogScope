# 多来源模拟故障场景与受控 Agent 验收

Status: ready-for-agent

## Problem Statement

现有模拟来源主要返回固定时刻的请求超时事件，能够验证查询、脱敏、判同和接口故障处理，但难以演示网关、订单应用、数据库及Redis之间不同层次的现象，也不足以评估Agent是否区分相关性、传播依据、关键矛盾和证据缺口。用户希望使用本机可重复的模拟来源，获得更有业务含义、可核查的调查结果。

## Solution

提供一组可在启动时选择的合成故障场景，通过现有只读HTTP模拟来源、服务目录、调查启动和Agent分析链路进入真实数据库及页面。第一组围绕订单服务，覆盖网关超时、应用依赖异常、数据库和Redis候选原因，包含仅相关、有传播依据、存在矛盾、空证据及部分来源不可用。

每个场景附带操作者可读的案例说明、固定查询范围、预期证据关系和允许的结论边界。说明中的答案及评分规则不发送给Agent。模型自由解释继续保存为待验证假设或未确定根因；不因样例存在预设原因而放松现有确认规则。

## User Stories

1. 作为本机操作者，我希望选择一个具名合成场景，以便重复演示同一故障。
2. 作为本机操作者，我希望知道场景涉及的服务与来源，以便正确配置调查范围。
3. 作为调查用户，我希望看到网关、订单应用、数据库和Redis的来源区别，以便理解不同层次的观测。
4. 作为调查用户，我希望只查询当前轮次登记的来源，以便避免其他服务日志混入。
5. 作为调查用户，我希望查询固定时间范围，以便刷新和重试仍能复核同一组材料。
6. 作为调查用户，我希望范围外日志不被纳入，以便保留覆盖边界。
7. 作为调查用户，我希望看到网关504与应用超时并存的案例，以便验证时间相关不等于因果证明。
8. 作为调查用户，我希望看到Redis依赖超时的候选解释，以便理解还缺少哪些验证材料。
9. 作为调查用户，我希望看到具有明确传播观测的案例，以便沿证据追溯请求失败路径。
10. 作为调查用户，我希望区分传播路径和最初故障原因，以便不把依赖超时直接解释为数据库故障。
11. 作为调查用户，我希望看到数据库资源异常候选场景，以便验证模型能处理依赖超时之外的问题。
12. 作为调查用户，我希望看到配置或权限异常候选场景，以便比较不同故障类别。
13. 作为调查用户，我希望同时存在多个可能原因，以便评估替代解释处理。
14. 作为调查用户，我希望关键矛盾被显式保留，以便模型不能选择性忽略反证。
15. 作为调查用户，我希望空证据正常结束为未确定根因，以便不将日志缺失等同于环境正常。
16. 作为调查用户，我希望部分来源不可用时明确显示缺失，以便不把局部材料当作完整覆盖。
17. 作为调查用户，我希望必要来源全部不可用时看到技术失败，以便区分无法排查与未找到原因。
18. 作为调查用户，我希望重复采集稳定身份的记录不增加证据条数，以便判断计数可信。
19. 作为调查用户，我希望不同来源的相同记录标识保持独立，以便避免跨来源误合并。
20. 作为调查用户，我希望敏感合成字段在交给Agent前完成脱敏，以便验证真实入口的保护。
21. 作为调查用户，我希望重复身份代号保持一致但不能据此确认原因，以便分开关联线索与因果证据。
22. 作为调查用户，我希望看到模拟来源标识，以便不误认为真实生产日志已经接入。
23. 作为调查用户，我希望页面刷新后仍看到相同证据及假设，以便复核已保存产物。
24. 作为调查用户，我希望手动新轮时历史仍保留，以便比较场景分析结果。
25. 作为调查用户，我希望人工严重程度不被场景或模型覆盖，以便保留决策权。
26. 作为调查用户，我希望取消后不再接收迟到产物，以便保留执行边界。
27. 作为本机操作者，我希望切换场景只影响后续查询，以便历史产物不会被原地重写。
28. 作为本机操作者，我希望旧模拟场景仍可运行，以便现有演示及测试不回退。
29. 作为测试维护者，我希望确定性验收通过真实HTTP业务链路完成，以便不依赖框架内部节点。
30. 作为测试维护者，我希望操作者答案与模型可见证据分开，以便避免向模型泄露预期结论。
31. 作为测试维护者，我希望评估依据、引用、矛盾及缺口，以便不以JSON合法替代语义正确。
32. 作为本机操作者，我希望真实模型测试显式启用且受剩余预算约束，以便普通回归不会产生费用。
33. 作为本机操作者，我希望有可复现的启动、选择服务和绝对时间范围说明，以便无需猜测即可演示。
34. 作为本机操作者，我希望报告区分模拟来源、模型替身和真实百炼调用，以便准确理解验收结果。

## Implementation Decisions

- 复用现有单Agent、LangChain百炼适配、LangGraph受控工具循环及业务事务边界；本需求不引入多Agent或新的日志平台依赖。
- 复用本机独立只读HTTP模拟服务。场景由操作者在启动时选择，不新增浏览器中的任意文件、URL或场景修改接口。未知场景启动失败，不静默回退到正常数据。
- 分开业务场景和已有协议故障场景。已有正常、空、权限、凭据、参数、临时错误、限流及超时模式保持原契约。新场景可为不同来源配置不同结果，故障计数按场景及来源隔离，不能沿用全进程共用计数造成串扰。
- 首批来源标识固定为模拟用途，涵盖网关、订单应用、数据库及Redis；同一调查服务可以登记多个相关来源。来源身份由服务端配置与查询参数决定，不能由模型指定或根据日志文字推断。
- 案例目录提供场景标识、中文说明、服务选择、来源列表、固定带时区时间范围、预期材料关系及分析边界。前端不必新增场景管理页；现有服务选择、证据卡片、覆盖信息、Agent状态和逐轮历史完成演示。
- 来源对source_id严格分流；未知来源返回可理解参数错误。返回材料的来源必须与请求一致；起止范围左闭右开，查询记录保留实际范围。不同来源的相同稳定记录ID不误合并，同一来源同一身份重复获取保持判同。
- 保留现有响应条数、字节数、材料长度和字段白名单；不把整个原始日志文本塞入身份字段或错误码，不把业务原因硬编码为Agent结论。
- 优先使用现有受控事件协议表达请求失败、依赖失败和传播观测。网关504、数据库资源耗尽等无法准确表达的观测必须通过最小版本化结构扩展，定义固定组件角色、受控观测类型及有界数值/单位，拒绝任意自由文本和未知字段。不得将Redis或数据库身份从邮箱、令牌、代号或错误发生时间推断出来。
- 结构扩展同时覆盖输入校验、脱敏、证据投影、模型可见上下文和页面展示；保留旧协议读取及既有证据身份语义。仅在现有JSON材料无法兼容时才提议数据库迁移，不预先安排表结构改造。
- 合成凭据和个人信息只用于验证现有脱敏入口。组件角色等确需参与分析的非敏感受控事实不应全部转成无语义代号；源URL和内部定位信息仍不直接暴露。
- 案例数据与操作者的预期解释、已知原因、评分规则分开。模型仅取得本轮合法脱敏观测和现有有限问题上下文，不发送场景答案、测试断言或评分。
- 仅相关案例提供多层相近时刻失败，但不提供充分传播证明；模型必须保留候选解释与缺口。有传播依据案例只证明明确声明的传播关系，不证明依赖为何失败。
- 矛盾案例同时提供可信候选依据与未解决矛盾；服务端现有保护不得因新材料版本丢失。空证据不证明无故障，部分缺失不证明未出现其他原因。
- 数据库资源、配置或权限案例允许模型提出多个类别的假设；分类名称本身不构成正确性证明。一般模型自由解释仍不得标为已确认根因；旧受控协议的固定确认路径与模型解释保持区分。
- 新数据可稳定复现，身份和发生时刻不随机漂移。切换场景后不修改已保存证据；同身份内容变化遵守既有冲突拒绝规则。文档建议切换时新建调查；不通过强制覆盖规避冲突。
- 保留单轮十分钟、单次查询三十秒、最多额外两次重试和2/5秒等待、最多三调查、取消和失联占位、重启不恢复旧图、人工等级确认等既有契约。
- 真实百炼继续使用北京qwen-plus、关闭thinking、仅只读工具、默认关闭付费测试。原累计人民币10元是所有联调合计预算，不是本功能新增10元；实施前核对已有估算、未知预留及账号账单，无法估价不发起调用。

## Testing Decisions

- 拟继续使用已确认的最高主要测试边界：业务HTTP API + 真实PostgreSQL + 独立HTTP模拟来源；通过创建、启动、查询、读取详情验证材料、范围、覆盖、身份、状态与持久化。测试模型替身仅替换付费外部模型，不替代业务状态。
- 少量Chromium E2E复用现有服务选择、启动、证据详情、Agent状态及历史查看，验证多来源可区分、刷新一致、模拟标识明确、错误/空状态和手机视口。无需逐个场景复制整套UI用例。
- 参考已有模拟来源协议集成、日志来源页面、Agent运行、证据脱敏、截止裁决、发布升级与活动子进程重启测试。仅在外部HTTP适配协议需要精确边界时补低层契约测试，不绑定LangGraph节点名、私有方法或模型固定措辞。
- 第一组验收：同一固定范围返回正确来源；范围外不纳入；稳定重复只计一次；跨来源相同ID独立；非法来源不混入；重复请求与新轮历史保持；未脱敏合成秘密不出现在持久材料、模型输入、错误和报告中。
- 场景验收：相关材料不确认原因；传播材料引用可核验；关键矛盾强制可见；资源/配置/权限能准确保留观测并产生有依据或明确不足的分析；空证据与必要来源不可用终态区分；部分来源失败显示覆盖缺失。
- 新协议若需要扩展，先补旧协议兼容、非法枚举、超长值、单位、数值范围、敏感/未知字段和历史读取测试；禁止为了让场景通过而放宽现有任意文本入口。
- 真实百炼代表案例在显式启用后运行，至少覆盖仅相关、传播依据、矛盾、空/部分缺失及新增故障类别。保存脱敏引用、用量、费用和逐项语义评审；发现无依据推断如实记录，不通过重试挑选好答案宣称可靠。
- 语义判定关注观测与假设是否区分、来源和范围是否正确、引用是否存在、是否保留矛盾、建议是否只读及服从范围、严重程度是否人工确认。JSON合法和候选分类正确均不是充分通过条件。
- 最终运行相关回归、类型检查、构建和一次完整套件。测试报告说明付费跳过、真实调用与替身范围，避免重复计数。
- 上述复用边界拟沿用前序认可的测试方式；本次需用户确认这些边界适用于多来源场景后，再发布实施工单和开展实现。

## Out of Scope

- 真实Nginx、Elasticsearch、Loki、数据库、Redis或Kubernetes连接器及真实只读账号权限验收；不勾选A33或完整A34。
- 启动真实依赖集群、制造生产故障、压测、JMX指标采集或生产日志上传。
- 任意本地文件导入、原始文本日志解析、自由格式JSON回放、生产历史日志回放；这些是后续独立需求，不因列为可选来源就自动纳入。
- 模拟Kubernetes、容器OOM全链路；首批只覆盖已讨论的订单、网关、数据库和Redis场景。
- 前端场景编辑器、热切换管理接口、自动修复、多Agent、自动恢复旧执行、登录/RBAC和组织隔离。
- 扩大模型结论确认能力、保证普遍推理质量或自动将场景预设原因显示为调查结论。
- 修改归档契约、重开已完成工单20，或替代父工单19尚未完成的原始范围。
