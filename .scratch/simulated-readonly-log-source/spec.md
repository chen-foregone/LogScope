# 可控模拟只读日志来源

## Problem Statement

用户目前没有可授权访问的真实日志来源，工单18因缺少来源协议、只读权限和安全接入契约而无法开工。现有受控查询可以记录来源状态，但不会自动把查询返回的日志保存为证据，因而无法通过完整场景理解来源查询、脱敏、可靠判同、失败处理及页面证据条数之间的关系。

需要先提供可运行、可观察、可重复验证的模拟来源，使用户能够完成开发和模块学习，同时不把合成日志、受控故障或模拟权限验证冒充真实来源验收。

## Solution

提供独立运行的本地只读 HTTP 模拟日志服务，以及通过该协议访问它的后端来源适配器。通过已有业务 HTTP API 发起查询，将返回材料经过固定范围和执行身份校验、受控结构化转换、脱敏及可靠判同后纳入本轮证据，并在现有调查详情中展示来源状态和证据条数。

仅显式启用本地开发配置才能连接模拟来源。页面和运行说明明确标识模拟来源。故障场景从开发启动配置或测试夹具选择，不向普通用户开放故障注入接口。真实接入继续由原工单18单独验收。

发布工单：[01：接通可控模拟只读日志来源](issues/01-connect-simulated-readonly-log-source.md)。

## User Stories

1. 作为开发者，我希望无需真实日志账号即可启动模拟来源，以便验证完整采集链路。
2. 作为开发者，我希望后端通过实际 HTTP 请求访问独立模拟服务，以便验证协议适配而非仅调用内存替身。
3. 作为使用者，我希望页面明确显示模拟来源，以便不将演示材料误认成生产证据。
4. 作为使用者，我希望查询仅使用本轮固定服务、来源及时间范围，以便结果符合调查范围。
5. 作为维护者，我希望查询和材料写入绑定有效调查尝试及执行身份，以便失效执行不能纳入产物。
6. 作为维护者，我希望浏览器无法指定来源地址或凭据，以便防止任意网络访问及范围绕过。
7. 作为开发者，我希望模拟来源只提供读取能力，以便验证被调查环境不被修改。
8. 作为维护者，我希望本地模拟配置默认关闭，以便不将演示服务带入默认运行环境。
9. 作为使用者，我希望查询返回的合法日志被保存为脱敏证据，以便页面展示实际材料而非单纯成功状态。
10. 作为维护者，我希望合成敏感字段在落库、展示和提供分析材料前脱敏，以便验证安全边界。
11. 作为维护者，我希望不支持的格式、未知字段和自由文本被拒绝，以便不以不可靠清洗代替脱敏契约。
12. 作为使用者，我希望同一稳定记录重复返回只计一次，以便证据条数可靠。
13. 作为使用者，我希望不同记录即使文本相同仍独立保留，以便不把内容相同当成同一记录。
14. 作为使用者，我希望缺少可靠身份的记录逐条保留并提示可能重复，以便了解计数限制。
15. 作为使用者，我希望同一可靠身份发生内容冲突时拒绝本次材料并保留旧证据，以便不覆盖历史事实。
16. 作为使用者，我希望查询无记录时仍能理解覆盖提示，以便不将查不到解释为没有异常。
17. 作为开发者，我希望可复现网络故障、超时、权限、凭据和参数错误，以便验证正确分类及有限重试。
18. 作为开发者，我希望可复现限流及跨调查来源竞争，以便验证新请求键不能绕过共享闸门。
19. 作为使用者，我希望部分来源失败时看到缺失来源且仍保留成功来源材料，以便继续有边界的调查。
20. 作为使用者，我希望必要来源持续不可用时按现有规则结束失败且保留此前材料，以便区分技术失败与证据被撤销。
21. 作为使用者，我希望取消或到期后旧执行不再写入，并在实际退出后才确认停止，以便避免迟到结果污染调查。
22. 作为开发者，我希望数据库报错和客户端未收到响应时能按已有幂等规则恢复，以便不重复计数或虚构成功。
23. 作为使用者，我希望刷新或重启后查询状态和已保存证据仍可读取，以便不依赖前端临时状态。
24. 作为学习者，我希望看到实际公开入口、调用链、表关联和状态规则，以便能够讲清模块而非只看到测试成绩。
25. 作为学习者，我希望通过业务结果预测及事务故障问答练习，以便理解接口返回与最终数据库效果可能不同。
26. 作为维护者，我希望明确模拟阶段已证明和未证明的边界，以便后续真实接入不会跳过验收。

## Implementation Decisions

- 本规格交付工单18本期模拟接入；真实来源门槛只约束后续真实接入，不阻塞本期，也不宣称满足真实来源验收组A33。
- 复用现有 Vue 页面、FastAPI 路由、SQLAlchemy Core 表及 PostgreSQL；不引入新框架、全局状态或无必要依赖。
- 模拟来源作为独立本地 HTTP 服务运行，使用合成结构化数据，不读取开发机器上的真实日志或其他被调查环境。启动说明给出可重复数据和演示范围。
- 来源访问契约为只读、有界查询，按服务端受控来源映射及半开时间范围返回结构化记录；固定小规模夹具，不默默截断数据或把未消费分页视为完整覆盖。协议、数量/体积上限及超限安全失败行为须在实现方案中具体列出。
- 只读服务不提供修改配置、重启和删除日志能力；测试对这些操作的拒绝，只证明模拟协议，不证明真实系统权限。
- 后端端点由服务端开发配置确定，默认关闭；不得接受浏览器提交的URL、查询表达式或凭据。模拟服务默认绑定回环地址，故障场景从启动配置或测试夹具注入，不提供普通业务故障控制入口。
- 凭据如协议确有需要，只通过安全运行配置注入，不写入工单、报告、浏览器、错误响应或持久诊断；模拟服务不得使用真实账号凭据。
- 来源标识及能力元数据区分模拟模式、协议版本与稳定身份支持；页面只显示必要的安全信息，不透传原始端点。已有历史记录不得因当前配置变化而被误标为真实来源。具体持久化及迁移方案在实现方案中列出，不能只靠临时前端标签。
- 查询继续使用现有受控业务入口和请求键，固定本轮范围，不新增浏览器直接执行来源查询的能力。
- 当前适配器成功契约仅接受异步查询返回空值，不支持日志数组。实现必须显式设计兼容演进：由受控查询编排把协议结果送入共用证据处理能力，而不是简单改变返回值后沿用现有成功判断。
- 现有证据入口和新增采集路径复用同一套严格结构校验、脱敏、范围校验、可靠判同及纳入逻辑；不复制另一套算法。内部共用写入仍需重新校验有效身份及截止时间，不依赖来源请求开始时的校验结果。
- 来源HTTP等待不持有数据库业务锁。沿用调查先于轮次的锁顺序、有序来源闸门、持久活动查询和最终截止裁决；不得绕过既有停止与失联恢复协议。
- 原始返回仅在受控内存处理；只有通过现有脱敏契约的材料可以保存及展示。不支持任意自由文本清洗；无法可靠转换的材料拒绝纳入并留下固定安全提示。
- 来源成功读取、证据保存和调查终态是不同事实。读取成功不表示每条材料均可纳入，更不表示没有异常。来源状态不得在其结果尚未完整处理时提前发布为成功。
- 证据按独立短事务纳入；本次后续记录、进度或最终事务失败，不撤销此前已经提交的证据。未经提交的证据、纳入关系和更新时间作为同一事务回滚；重试依靠可靠身份判同。不得将采集批次描述成全有或全无。
- 同一来源内稳定记录ID作为可靠身份演示；另含不同ID同文本、同ID内容冲突及无身份样本。禁止用文本哈希或时间近似伪造可靠记录身份。
- 沿用本轮10分钟总预算、每次最多30秒、临时故障额外最多两次及退出后2秒/5秒等待。权限、凭据、参数错误不盲重试；限流映射遵循模拟协议明示值并复用共享闸门。
- 部分来源失败及全部来源不可用沿用当前实现规则，缺失状态真实展示；不新增未经定义的必要/可选来源策略。不把模拟来源查询成功改写为根因确认或自动完成调查。
- 不依据记录读取结束推断执行退出；取消、超时和失联后禁止旧执行写入，保持既有退出确认流程。真实HTTP操作的取消及连接清理必须测试。
- 实施前仍先列出接口、状态、文件变更、迁移风险和分批验证方案；本规格的发布状态不替代用户要求的方案确认，也不是立即写完整代码的授权。

## Testing Decisions

- 主要验收缝沿用业务 HTTP API + 真实 PostgreSQL，并让适配器访问独立运行的本地 HTTP 模拟来源。优先断言响应、详情、重启后读到的状态及可观察的来源请求，不以内部函数调用次数或私有实现结构作为主要验收。
- 另以浏览器端到端测试确认来源模拟标签、查询状态、缺失提示、脱敏片段及证据条数，API与UI一致。必要的协议边界测试只补充主验收缝，不另造多套业务替身。
- 沿用现有查询测试中的快照调用、幂等重放、跨调查来源闸门、部分失败、持久化和最终事务故障模式；沿用证据测试中的可靠身份、并发冲突、禁止原文持久化和数据库回滚模式；沿用时限测试中的跨截止最终裁决及取消实际退出模式。
- 正常链路覆盖启动模拟服务、发起轮次、查询、保存脱敏证据、读取详情、刷新及重启。验证空结果可以查询成功但不产生证据，且不输出无异常结论。
- 身份用例覆盖同记录在一次响应内重复、跨查询重复、不同ID同文本、来源不同、无可靠身份和同身份内容变化；不把无身份重试产生的重复当成可靠判同成功。
- 安全用例覆盖篡改来源/范围/身份、无凭证或失效执行、未知字段和自由文本、合成敏感字段、读取/响应体积超限、错误体含敏感值；通过响应、持久材料及诊断观察不泄漏原文。
- 故障用例覆盖临时故障重试、权限/凭据/参数不重试、明确及未知恢复时间的限流、多个来源部分失败、跨调查争用、单次超时、总截止预算和查询取消。
- 故障注入覆盖证据插入后的数据库错误、若干证据已提交后后续采集失败、查询最终事务失败，以及客户端未收到成功响应后重试。明确哪些持久事实保留，禁止假定HTTP失败意味着全部回滚。
- 对真实HTTP取消、资源释放和30秒规则至少保留实际协议/实际时间验证；其余漫长场景可以复用可控时钟和调度，但报告中分开标记，不冒充真实等待测试。
- 人工构造数据库异常仅用于协议恢复与回滚测试，必须标记为异常夹具，不能声称正常用户流程可以产生该数据。
- 实施期间常规运行类型检查与单文件测试，最后运行完整测试套件并记录命令、结果及未执行原因。当前对话中的92项回归和类型检查仅是既有实现证据，不是本功能完成证据。
- 本次按“不再访谈、直接综合”和离线不等待教学回答的要求采用上述测试缝；未声称用户已经逐项确认。进入实现前在方案中显式呈现该边界。

## Out of Scope

- 真实日志供应商选择、真实账号开通、真实网络环境接入与真实权限证明。
- 工单18的真实协议验收和A33完成认定；模拟测试不能解除相关门槛。
- 真实Agent或自动根因分析接入、任意远程命令及被调查环境写操作。
- 任意自由文本日志的通用脱敏、生产级海量检索、供应商通用查询语言和完整分页框架。
- 新建登录/RBAC体系、重写现有执行恢复协议或扩展跨主机执行退出保证。
- 通过故障控制接口修改生产配置、把真实凭据或个人信息当作演示数据。
