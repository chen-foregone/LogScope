# LogScope

**基于日志证据的只读故障排查 Agent 工作台。**

LogScope 将一次故障排查组织为可追溯的调查：固定服务和时间范围，查询日志，脱敏并保存证据，再由 Agent 提出有依据的假设和核查建议。项目关注的不只是“让模型分析日志”，还包括执行控制、数据一致性和人工决策边界。

> 当前演示使用本机合成日志来源，可接入真实百炼 `qwen-plus`。业务 API 和 PostgreSQL 持久化是真实实现，但不代表已接入生产日志平台或具备生产级根因判断能力。真实模型默认关闭。

## 为什么做这个项目

直接把日志交给大模型，容易得到难以复核的解释，也难以回答这些问题：结论引用了哪条日志？日志是否已脱敏？取消后模型还能否写入？重新排查会不会覆盖历史？

LogScope 将日志、证据、调查状态和模型产物分开管理：

- **先有证据，再谈判断**：保留来源、发生时间、查询范围和核验材料；模型自由解释只能形成假设，不因自报“已确认”而升级为根因。
- **执行过程可控**：固定单轮范围，限制并发和总时限，隔离取消、超时或失联执行的迟到写入。
- **历史可以复核**：多轮分别保存范围、证据与结论；历史证据须显式校验后纳入新轮，不自动继承。
- **人保留决策权**：不提供自动修复工具，人工严重程度决定不能被 Agent 直接覆盖。

## 核心流程与功能

```text
创建待处理调查
    → 选择服务与日志时间范围
    → 启动一轮调查（固化范围与执行身份）
    → 只读查询 → 校验与脱敏 → 去重并保存证据
    → Agent 生成假设、证据引用与核查建议
    → 查看结果、人工评估，或手动开启新一轮
```

“已完成”只表示本轮排查结束，不表示已定位根因；技术失败、主动取消与证据不足分别表达。

| 能力 | 实现要点 |
| --- | --- |
| 调查工作台 | 创建、详情、搜索、服务及更新时间筛选、分页；概况统计全部匹配记录，而非当前页 |
| 多轮调查 | 手动重开、逐轮范围与历史；整体状态跟随最新轮，不改写旧轮 |
| 证据管理 | 保存前脱敏、调查内一致代号、可靠身份去重、历史引用与来源追溯 |
| 证据核验 | 区分来源不可访问与材料不可核验；关键依据不足时进入“待重新核验”，保留变化历史 |
| 受控 Agent | LangGraph 单 Agent、受限只读工具、结构化输出、引用校验与累计费用预算 |
| 人工严重程度 | 未评估／低／中／高；人工决定优先，新建议需确认，保留变更历史 |
| 归档与清理 | 未归档持续保留；归档后 30 天自动清理；手动删除需预览确认，其他调查仍需材料时拒绝清理 |

## 技术架构

| 层次 | 技术 | 职责 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Element Plus | 调查工作台、页面状态、证据与历史展示 |
| 后端 | FastAPI、Pydantic、SQLAlchemy 2 | 输入校验、调查与执行状态、证据处理、事务与接口 |
| 持久化 | PostgreSQL 17、Alembic | 调查、轮次、执行身份、证据引用、变更历史、预算账本及迁移 |
| Agent | LangGraph、langchain-openai、百炼 qwen-plus | 有界单 Agent 编排、只读查询与结构化分析 |
| 验证 | pytest、httpx、Playwright | API、真实数据库、并发与重启、浏览器流程及模型评估 |

```text
Vue 调查工作台
    │ HTTP /api
    ▼
FastAPI ───────────────────────────── PostgreSQL
    │                                调查 / 轮次 / 证据 / 历史 / 预算
    ├─ 生命周期控制：启动、取消、截止时间、失联确认
    │
    └─ LangGraph 单 Agent ─────────── 百炼 qwen-plus
          │ 受限查询工具                   ▲
          ▼                                │ 脱敏证据
       查询编排 → 模拟 HTTP 日志来源 → 校验 / 脱敏 / 纳入
```

模型不直接访问数据库或任意日志地址；后端负责固化查询范围、核验执行身份，并决定产物能否落库。业务数据库中的事实是执行授权依据，不以图 checkpoint 代替。

## 关键工程设计

### 1. 并发控制不只靠按钮禁用

同一调查最多一轮运行，实例同时最多运行 3 个调查。接纳通过 PostgreSQL 持久锁及事务内校验完成，避免多个请求同时检查后都启动。满额直接拒绝，不创建伪运行轮次，也不后台排队。

### 2. 请求取消不等于执行已经结束

取消先隔离产物写入，界面显示“正在停止”；只有确认执行终止后才进入“已取消”并释放名额。超时和失联同样保守处理，旧执行不能借迟到响应写入证据、结论或等级。当前退出确认主要覆盖本机 Windows 受控执行，不泛化为任意远程执行器的安全保证。

### 3. 重试、幂等和终态竞争分开处理

单次查询超时 30 秒，临时故障最多额外重试 2 次，等待 2 秒、5 秒；单轮共享 10 分钟预算。权限、凭据与参数错误不盲重试。创建、启动等操作按各自请求身份处理重放；完成、取消、超时按事务中的持久事实裁决，避免互相矛盾的终态。

### 4. 去重不能只比较日志文本

优先使用来源与稳定记录 ID，或稳定文件身份与偏移。没有可靠身份时保留材料并提示可能重复，不因脱敏后文本相同就合并。原始证据与逐轮纳入关系分开保存，历史引用不会覆盖原轮记录，也不代表新轮范围已完整覆盖。

### 5. 模型输出不是业务事实

日志先脱敏，输出再经过 Pydantic Schema、引用与业务约束校验。模型候选分类与结构化观测方向分别保留；时间相关、共同关联标识或模型自报确认，都不能单独证明因果关系。建议由服务端限制为当前范围的只读核查项，不提供 Shell、任意 SQL、重启或修复工具。

### 6. 模型费用也是持久状态

调用前预留最大输入／输出费用，成功且 usage 合法时结算；超时或用量不明时保留预留，不盲目退款。预算是数据库共享累计额度，不是每轮重新发放；重启和删除调查不会重置预算。

## 快速开始

以下命令在仓库根目录的 **Windows PowerShell** 执行。准备 Python 3.13、Node.js 22 和 Docker；当前受控 Agent 演示依赖可核验的本机 Windows 进程身份。

### 1. 安装依赖并启动数据库

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
npm ci
docker compose up -d postgres
```

等待数据库健康检查通过。Compose 默认账号仅供本机开发，不应用于共享环境；数据库端口不应暴露到不可信网络。

### 2. 配置并执行迁移

首次运行时将 `.env.example` 复制为 `.env`；已有 `.env` 时保留现有配置，不要覆盖。

```powershell
$env:PYTHONPATH='backend'
.venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade head
```

默认连接本机 `5432` 端口的 Compose 数据库，可通过服务端 `DATABASE_URL` 覆盖。应用不会用自动建表代替迁移。升级已有数据库前应备份并停止旧版本写入；归档规则见[保留模块说明](docs/retention-module.md)。

### 3. 启动 API

```powershell
.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

- 健康检查：[http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health)
- API 文档：[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

### 4. 启动前端

另开终端：

```powershell
npm run dev
```

访问 [http://127.0.0.1:5173](http://127.0.0.1:5173)，`/api` 由 Vite 代理至本机 API。

默认未启用模型、未配置服务目录：可创建和浏览调查，但不会自动采集日志或产生模型分析。完整演示按下一节配置。

## 演示：模拟日志与真实模型

### 启动合成故障来源

另开终端：

```powershell
$env:PYTHONPATH='backend'
.venv/Scripts/python.exe -m app.mock_logs --port 8091 --scenario database-pool
```

停止之前的 API，在 API 终端设置来源和服务目录后重新启动：

```powershell
$env:SIMULATED_LOGS_URL='http://127.0.0.1:8091'
$env:SERVICES_FILE='backend/services.simulated-incidents.json'
.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

这些配置只启用模拟来源，不会启用真实模型。若要由页面启动自动分析，还需按[Agent 联调说明](docs/agent-integration.md)安全配置 `DASHSCOPE_API_KEY`、核对地域与价格、确认累计预算，并显式设置 `AGENT_ENABLED=true` 后重启 API。不要把密钥写入前端、Git 或截图；真实调用会产生费用。

### 建议演示路径

1. 创建调查，选择“订单链路（合成场景）”。
2. 将日志范围设为北京时间 `2026-11-01 08:00:00` 至 `09:00:00`，而不是默认最近一小时；合成记录使用固定历史时间。
3. 启用真实模型后启动调查，查看来源覆盖、脱敏证据、观测方向、假设及核查建议。
4. 浏览证据引用和逐轮历史，区分“证据支持的观测”与“模型候选解释”。
5. 切换到噪声、多方向或来源缺失场景，观察系统如何保留不确定性，而不是强行输出唯一根因。

完整场景、切换方法和限制见[模拟故障场景](docs/simulated-incident-scenarios.md)。不配置付费模型时，可通过默认确定性测试验证工具链和业务约束，但不能将测试替身当作真实模型演示。

## 测试与验证

测试覆盖输入校验、幂等与并发、证据处理、取消／超时／失联竞争、迁移与重启，以及真实浏览器中的调查流程。数据库相关测试使用真实 PostgreSQL 隔离 schema，不以进程内列表代替持久化。

```powershell
# 安装测试依赖与浏览器
.venv/Scripts/python.exe -m pip install -r backend/requirements-test.txt
.venv/Scripts/python.exe -m playwright install chromium

# 前端类型检查与生产构建
npm run build

# 准备独立测试数据库后执行回归
$env:PYTHONPATH='backend'
.venv/Scripts/python.exe -m pytest backend/tests tests -q
```

运行前注意：

- **测试库与开发库分离**：默认测试配置使用 `127.0.0.1:55433/logscope_test`；通过 `TEST_DATABASE_URL` 配置连接，UI fixture 强制检查本机 `55433` 端口。仅启动开发 Compose 数据库不足以运行全部测试。
- **环境要求**：测试账号需具备创建隔离 schema 的权限；部分迁移／重启用例还依赖 Docker 工具。UI 测试默认占用 `8000`、`5173`，运行前先停止手动演示服务。
- **执行限制**：测试会启动子进程，部分用例依赖 Windows 进程身份；不要未经适配就假设跨平台全量通过，也不要同时运行争用端口的批次。
- **付费测试默认关闭**：真实模型测试需显式启用；连通成功、结构断言通过不等于完整语义正确，还需人工评审因果、矛盾与替代解释。

验证记录和已知模型偏差见[Agent 联调说明](docs/agent-integration.md)。这里不将不同批次测试数相加，也不以有限案例声称普遍模型准确率。

## 当前边界与后续方向

- **日志来源仍为模拟**：尚未完成真实供应商协议、生产只读账号及稳定身份能力验收。
- **不是自动修复系统**：不修改被调查环境，不执行模型建议，不保证模型能够准确定位所有根因。
- **面向本机受保护访问**：尚无面向公网多用户的完整登录、RBAC 和租户隔离；本地访问检查不等于用户鉴权，不可经未鉴权代理暴露公网。
- **执行安全有平台边界**：当前退出确认依赖本机 Windows 受控协议；跨主机、Linux 与其他执行器需独立设计和验证。
- **删除有明确限制**：运行中禁止归档或删除；应用清理不承诺同步物理擦除备份与数据库事务日志。

后续重点是接入真实只读日志平台、扩展可核验执行协议、完善用户及数据权限，并持续评估模型语义质量，而非只扩大工具数量。
