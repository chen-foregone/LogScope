# LogScope 产品手册

> 文档更新日期：2026-10-31
> 适用范围：当前仓库中的 LogScope 交互原型与本地开发骨架。本文依据源码和现有项目文档编写，未执行运行验收。

## 1. 产品介绍

LogScope 的产品定位是日志故障排查工作台，目标是帮助使用者从异常信号出发，组织调查过程，并将结论关联到可核验的日志证据。

**当前版本是交互原型，不是能够接入真实日志、执行检索分析或自动定位根因的完整系统。** 你可以体验调查列表展示、关键词搜索、服务筛选和新建临时调查记录；后端目前提供基础接口与数据库连接骨架。

### 1.1 当前可以做什么

- 浏览预置的四条示例调查记录。
- 按调查标题、服务名或调查编号搜索记录。
- 按服务筛选记录，并与关键词搜索组合使用。
- 创建仅在当前页面会话中保留的临时调查记录。
- 查看界面布局、示例概况、调查动态和数据源展示。
- 通过后端健康接口确认 API 能否响应。

### 1.2 当前不能做什么

- 上传或解析真实日志文件。
- 连接 Elasticsearch、Grafana Loki 或其他日志系统。
- 执行真实日志检索、自动调查、证据收集或根因分析。
- 保存调查到数据库、导出调查报告或跨会话恢复记录。
- 打开真实调查详情、编辑调查内容或变更调查状态。
- 使用登录认证、业务授权或多用户工作区。

> 页面上的“正常”“就绪”“证据完整率”等展示不能作为真实环境的监测结果。

## 2. 快速开始

### 2.1 准备环境

完整的本地开发启动流程涉及 Node.js/npm、Python，以及运行 PostgreSQL 的 Docker Compose。仓库没有明确声明 Node.js 和 Python 的最低版本，因此本文不额外承诺版本兼容范围。

以下命令均以项目根目录为工作目录。Windows 示例路径：

```text
C:/Users/c1342/WorkBuddy/log-scope
```

### 2.2 启动数据库

```bash
docker compose up -d postgres
```

数据库服务使用 PostgreSQL 17 Alpine 镜像，宿主机端口映射为 `5432:5432`，数据存放在命名卷 `logscope-postgres-data` 中。当前 Compose 仅启动数据库，不会自动启动前后端。

默认数据库名、用户名和密码均为 `logscope`。这些凭据仅适合本地开发；共享环境使用前必须调整。

### 2.3 启动后端

创建虚拟环境：

```bash
python -m venv .venv
```

Windows PowerShell 中激活：

```powershell
.venv\Scripts\Activate.ps1
```

Windows Git Bash 中激活：

```bash
source .venv/Scripts/activate
```

激活后安装依赖并启动 API：

```bash
pip install -r backend/requirements.txt
uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

| 入口 | 地址 |
| --- | --- |
| API 根路径 | `http://127.0.0.1:8000/` |
| 健康检查 | `http://127.0.0.1:8000/api/health` |
| 交互式 API 文档 | `http://127.0.0.1:8000/docs` |

默认配置下，健康检查返回：

```json
{
  "status": "ok",
  "service": "logscope-api"
}
```

**该响应只说明健康接口可以应答，不检查数据库、日志源或调查流程。**

### 2.4 启动前端

另开终端，在项目根目录执行：

```bash
npm install
npm run dev
```

默认访问 `http://127.0.0.1:5173`，实际地址以终端输出为准；项目未固定开发端口。

当前调查列表使用前端内存数据，并未调用业务 API。因此，页面能展示示例记录不代表后端或数据库已连接。

### 2.5 构建与预览

```bash
npm run build
npm run preview
```

构建会先执行 TypeScript/Vue 类型检查，再生成前端构建产物。预览端口以终端输出为准。开发配置中的 `/api` 代理不应视为生产部署方案。

## 3. 界面说明

### 3.1 导航与工作区

左侧包含“调查工作台”“日志检索”“服务目录”。当前点击导航仅改变选中状态与面包屑，主体仍是调查工作台，尚未实现独立的日志检索页或服务目录页。

页面展示的用户名、个人工作区与“本地开发环境／就绪”属于原型内容，不代表已具备登录、工作区切换或环境连通性检查。

### 3.2 概况卡片

| 卡片 | 当前含义 |
| --- | --- |
| 活跃调查 | 根据当前完整内存列表中状态为“调查中”的记录统计，不随列表筛选改变。 |
| 待处理告警 | 固定示例值，不连接真实告警系统。 |
| 已分析事件 | 固定示例值，不是日志分析计算结果。 |
| 证据完整率 | 固定示例值，不是证据覆盖评估结果。 |

### 3.3 调查列表

表格包含“调查”“服务”“严重程度”“状态”“事件数”“更新时间”。

- 严重程度展示为“高”“中”“低”。
- 当前前端状态包括“调查中”“已完成”“待处理”。
- 事件数是示例记录字段，新建记录为 `0`。
- 更新时间是展示字符串，没有自动计时刷新机制。

### 3.4 调查动态与数据源状态

“调查动态”是静态示例内容，不与新建记录或筛选结果联动。

“数据源状态”展示 Elasticsearch、Grafana Loki 和本地日志文件。其中 Elasticsearch、Grafana Loki 的“正常”只是原型文案，本地日志文件显示等待配置；当前均无实际连接或上传能力。

## 4. 典型操作

### 4.1 搜索调查

1. 在“搜索调查、服务或编号”输入关键词。
2. 表格即时显示匹配记录。
3. 清空输入恢复关键词条件下的全部记录；若仍选择某项服务，服务筛选继续生效。

搜索会去除关键词首尾空格，不区分大小写，以字面子串匹配调查标题、服务名和调查编号。它不搜索日志正文、严重程度或调查状态，也不支持正则和专用查询语法。

无匹配结果时，表格显示“没有匹配的调查记录”。

### 4.2 按服务筛选

1. 打开“按服务筛选”下拉框。
2. 选择要查看的服务。
3. 选择“全部服务”取消服务限制。

服务选项来自当前完整调查列表的服务名。关键词与服务筛选同时使用时，记录必须同时满足两项条件。

### 4.3 新建临时调查记录

1. 点击右上角“新建调查”，或侧栏“最近调查”旁的加号。
2. 页面在完整列表开头插入一条新记录，并提示创建成功。
3. 如没有在表格中看到记录，先清空搜索并将服务筛选切回“全部服务”。

新记录的默认内容：

| 字段 | 初始内容 |
| --- | --- |
| 调查标题 | 新建日志调查 |
| 服务 | 待选择服务 |
| 严重程度 | 低 |
| 状态 | 调查中 |
| 事件数 | 0 |
| 更新时间 | 刚刚 |

**此操作不会弹出配置表单，也不会启动真实调查。** 当前不能继续为记录选择服务、配置时间范围或编辑标题。

记录只存在于当前页面内存中，刷新页面会丢失。编号由前端生成，不应作为跨会话唯一标识使用。

### 4.4 识别尚未生效的控件

| 控件 | 当前行为 |
| --- | --- |
| 时间范围：近 1 小时／近 24 小时／近 7 天 | 可改变选项，但不参与记录筛选。 |
| 最近更新 | 仅显示提示，不执行排序。 |
| 调查标题 | 提示详情准备中，不打开详情。 |
| 侧栏最近调查 | 仅显示提示，不打开详情。 |
| 查看全部 | 仅显示提示，没有分页或加载更多。 |
| 设置 | 提示后续版本开放。 |
| 通知 | 提示暂无新通知。 |
| 更多动态 | 提示暂无更多动态。 |
| 数据源区域的管理 | 仅将导航选中项改为服务目录。 |
| 用户菜单 | 未绑定操作。 |

## 5. 配置说明

### 5.1 后端配置

后端通过配置类读取 `.env`，编码为 UTF-8。配置文件路径未写成绝对路径，建议从项目根目录启动服务。仓库 `.env.example` 提供数据库连接配置示例。

| 配置字段 | 默认值 |
| --- | --- |
| `app_name` | `LogScope API` |
| `database_url` | `postgresql+psycopg://logscope:logscope@localhost:5432/logscope` |
| `api_prefix` | `/api` |

数据库连接可通过 `DATABASE_URL` 环境配置覆盖。更改 API 前缀时，健康接口路径也会改变，相关代理和调用方需同步检查。

> 只修改后端 `.env` 并不会同步修改 Compose 中的数据库账号密码；两处配置需要保持一致。

### 5.2 前端开发代理与 CORS

- 开发服务器将 `/api` 请求代理到 `http://127.0.0.1:8000`。
- 后端 CORS 配置列出 `http://127.0.0.1:5173` 和 `http://localhost:5173`。
- 如果开发端口变化，直接跨域访问 API 时需要检查允许来源配置。
- 当前前端列表未对接业务 API，因此代理存在不代表调查数据已连通。

## 6. 数据与安全

### 6.1 数据保存边界

当前调查数据保存在浏览器页面内存中，没有数据库持久化或浏览器本地持久化。PostgreSQL 命名卷仅提供数据库存储基础，不代表产品已经把调查记录写入数据库。

目前没有定义可用的日志上传大小限制、支持扩展名、编码、保留期或配额，因为上传和日志存储功能尚未实现。不要将“未定义”理解为“不限大小”或“支持所有格式”。

### 6.2 使用注意

- 不要把当前原型直接作为生产日志排查或监控依据。
- 不要将默认开发数据库凭据用于共享或生产环境。
- Compose 的数据库端口映射未限定本机回环地址，网络访问边界还需检查宿主机配置与防火墙。
- 尚无登录认证和业务授权；“只读调查模式”是产品约束文案，不是已经实现的权限系统。
- 项目样式引用 Google Fonts，受限网络或离线环境下外部字体可能无法加载。
- 不要根据静态“正常”“就绪”状态判断日志源或数据库是否可用。

## 7. 产品术语与规则

术语以项目根目录的 [GLOSSARY.md](../GLOSSARY.md) 为准。

| 术语 | 使用说明 |
| --- | --- |
| 被调查环境 | 被分析的目标环境。不得因调查而擅自修改。 |
| 调查产物 | 调查记录、证据与结论等产出；与被调查环境区分。当前未实现产物持久化。 |
| 只读调查 | 不修改被调查环境；不等于禁止保存调查产物。 |
| 已完成 | 不自动等同于已找到或确认根因。 |
| 失败 | 表示技术故障导致中止，不等于未找到根因。当前前端尚无该状态。 |

项目已明确的产品规则还包括：证据不足不能认定根因，缺失日志源应说明证据覆盖限制，调查启动前应确定服务和日志时间范围。

**上述规则尚未全部落地。** 当前“新建调查”直接生成服务为“待选择服务”、状态为“调查中”的记录，也没有调查时间范围字段，与正式启动条件存在冲突。因此应将其视为原型交互，而非符合完整产品规则的调查流程。

## 8. 常见问题

### 为什么刷新后新建调查不见了？

调查只保存在当前页面内存中。刷新会重新加载示例记录，当前没有恢复或导出机制。

### 为什么新建成功后列表里看不到？

新记录的服务名固定为“待选择服务”，标题固定为“新建日志调查”。当前关键词或服务筛选可能将它排除；清空搜索并选择“全部服务”后再查看。

### 为什么改变时间范围没有效果？

目前时间范围仅更新界面选项，没有参与数据筛选。

### 数据源显示正常，是否说明连接成功？

不是。当前数据源状态为静态展示，没有连接或探测逻辑。

### 可以上传哪些日志格式？

当前不能上传日志，因此没有已实现的格式支持清单。`.log`、JSON、CSV 等格式都不能依据当前界面推断为已支持。

### 健康接口返回正常，是否说明数据库正常？

不是。健康接口返回固定状态，没有进行数据库或日志源连通性检测。

### 为什么能打开前端，却没有真实调查结果？

当前前端以本地示例数据展示，后端未提供调查业务 API，Agent 流程也尚未实现。

### 为什么点击日志检索或服务目录后内容没有切换？

当前仅切换导航高亮与面包屑，没有实现独立页面。

### 为什么 API 或数据库启动失败？

本手册未执行启动验收。可先查看对应终端输出，检查依赖安装、端口占用、数据库容器状态和连接配置是否一致。页面上的静态状态不可用于诊断这些问题。
