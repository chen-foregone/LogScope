# 多来源模拟故障场景

这些场景是本机合成日志，经过独立只读HTTP来源、真实业务API/PostgreSQL及Agent工具链。它们不连接真实网关、数据库或Redis，也不证明真实供应商权限或完整A33/A34验收。

## 启动与调查范围

先按项目既有说明启动PostgreSQL、执行迁移、启动前端。另开终端运行模拟来源：

```powershell
$env:PYTHONPATH='backend'
.venv/Scripts/python.exe -m app.mock_logs --port 8091 --scenario database-pool
```

业务API终端使用多来源服务目录：

```powershell
$env:PYTHONPATH='backend'
$env:SIMULATED_LOGS_URL='http://127.0.0.1:8091'
$env:SERVICES_FILE='backend/services.simulated-incidents.json'
# DATABASE_URL及EXECUTOR_CREDENTIAL沿用本机安全配置。
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

真实Agent默认关闭；启用方式、北京地址、价格和凭据注入见[Agent说明](agent-integration.md)。使用模型替身的自动测试不会发付费请求。修改环境变量后须重新启动承载API的终端/进程，确保不继承旧配置，不打印密钥核对。

页面创建调查，选择“订单链路（合成场景）”，采用绝对范围：

- 开始：`2026-11-01T08:00:00+08:00`
- 结束：`2026-11-01T09:00:00+08:00`
- 对应UTC：`2026-11-01T00:00:00Z` 至 `2026-11-01T01:00:00Z`，左闭右开。
- 合成观测发生于UTC `00:15`。默认最近一小时通常没有这些历史记录，应显式选择上述范围。

启用Agent后手动启动即可在调用预算内采集并分析，刷新详情查看已保存产物。未启用Agent时，仍沿用既有受控执行接口的只读查询流程；浏览器不持有执行凭据。整个调查最多10分钟，历史日志范围不等于执行预算。

## 操作者案例目录与评审参考

下表是操作者答案及评审提示，不发送给模型。模型取得的只有本轮脱敏证据、受控角色、来源覆盖及有限问题提示。

| 场景 | 观测与正常证据条数 | 应有分析边界 |
| --- | --- | --- |
| `order-correlation` | 网关504、订单请求超时，2条 | 时间相近和共同关联代号不足以证明因果，更不能确定数据库或Redis故障。 |
| `redis-timeout` | 前述观测及Redis依赖超时，3条 | Redis是有观测支持的候选方向，缺少同调用传播证明，仍需核验。 |
| `redis-propagation` | 三层观测，订单事件另有受控传播轨迹，3条 | 轨迹支持其声明的错误传播关系；不能据此证明Redis最初为何超时。轨迹未命名具体依赖，不能单凭相近时刻把它与特定Redis事件强行绑定。 |
| `redis-contradiction` | 同上，但轨迹标记未解决矛盾，3条 | 服务端强制保留未解决矛盾、未知传播路径及缺口；模型不能排除其他原因。 |
| `database-pool` | 网关504、订单超时、数据库连接池100/100，3条 | 容量观测支持资源方向；不证明连接泄漏、慢SQL、锁等待或某项配置是根因。 |
| `configuration-missing` | 网关504、应用配置缺失，2条 | 配置缺失是观测；未记录具体配置名与因果传播，不能编造设置项或直接确认504原因。 |
| `permission-denied` | 网关504、应用EACCES，2条 | 权限拒绝是业务日志观测，并非来源查询403；不能编造账号、资源或具体权限修复。 |
| `order-empty` | 四个来源正常返回空，0条 | 正常结束可未确定根因；空日志不证明环境正常，不编造不存在的证据ID。 |
| `order-partial` | 网关/应用正常，数据库/Redis来源查询403，2条 | 展示两个缺失来源和不完整覆盖；不能据此排除数据库/Redis原因。 |
| `order-unavailable` | 四个来源查询均403，0条 | 必要来源全部不可用属于技术失败，保留可理解原因，不伪装为正常完成或已定位原因。 |

每个有观测的来源返回两个相同稳定身份的材料，纳入后只计一次；不同来源使用相同记录ID仍独立。空的成功来源说明没有返回记录，不保证来源内所有故障均已被观测。四项概况继续统计最新轮纳入证据，而非HTTP响应条数或故障数量。

切换场景时停止并重启模拟服务，建议新建调查。若在同一调查新轮使用同一可靠身份但改变原始事件内容，既有身份冲突保护会拒绝变更，不覆盖旧证据。新轮不会自动继承历史材料；相同记录的合法重新获取沿既有机制纳入。

## 受控观测协议

HTTP外层继续使用 `simulated-logs-v1`，成功项允许旧 `controlled-event-v1` 及新 `controlled-event-v2`，定位材料v1也保持兼容。V2在record中要求observation，不接受任意日志message；v1不能夹带v2字段。所有新字段以JSON材料增量保存，不新增数据库表或迁移。

组件仅允许gateway、application、database、redis。观测类型仅允许HTTP响应、请求超时、依赖超时、连接池占用、配置缺失和权限拒绝。HTTP状态100–599；连接数为整数、使用量非负且不大于容量、容量1–1,000,000、单位固定connections；不接受布尔代替数值、未知字段或不一致事件/错误码。HTTP 504保存在独立状态字段，不伪造原v1错误码。

服务目录可选source_roles以受控枚举声明来源角色，键必须在登记来源中，共享来源角色不能冲突。模拟适配器绑定该角色；V2材料冒充其他组件会被拒绝。旧目录无需新增字段仍可使用。角色来自服务端配置，不由模型选择，不发送原始source_id或URL；模型上下文保留安全来源代号及角色以匹配缺失覆盖。

角色、信号和有界计量保留分析语义；凭据仍直接屏蔽，身份和关联标识仍调查内代号化。源URL、定位、原问题自由文本、操作者答案均不会作为新观测透传。响应最多1MiB/100条，每条材料沿用64KiB入口限制。

本轮只要存在有效V2观测，服务端就约束Agent的最终展示：模型仅提供候选分类和有效证据选择，现象、解释、替代方向、矛盾、缺口及只读建议由受控观测生成。事实描述只使用被引用的观测；未引用V2（含空引用或混合轮次只引用V1）时明确提示引用不足。结构化矛盾始终保留。模型自由文本不进入这些展示字段，旧的纯V1分析行为保持兼容。这是保守的证据展示能力，不代表模型已具备可靠的自由根因推理能力。

后续完善将model_category与observed_directions分开：前者保留未验证模型分类，后者只按被引用的权限/配置/容量/依赖观测归类并关联证据；仅超时或多个不同方向时汇总分类保持未知。所有新Agent产物（包括纯V1）的建议字段统一采用服务端只读核查项；V1历史及因果字段不改写。Agent引用失效会呈现待重新核验，人工新轮恢复后依据再次失效也会重新降级。详情见[后续验收](../.scratch/agent-quality-followup/validation.md)。

旧normal、empty、unidentified、conflict、invalid、permission、credentials、parameters、temporary、limited、timeout模式继续可用。temporary的前两次503现在按来源分别计数，避免其他来源提前耗尽重试次数；新业务场景拒绝未知来源。没有在线场景编辑、任意URL或文件上传接口。

## 测试和真实模型

主边界是业务HTTP API、真实隔离PG与独立HTTP模拟来源；浏览器补充多来源结构化观测、390px视口和刷新。模型替身验证流程和强制边界，不能证明真实模型语义。

```powershell
$env:PYTHONPATH='backend'
$env:PGOPTIONS='-c max_parallel_workers_per_gather=0'
$env:AGENT_BASE_URL='https://dashscope.aliyuncs.com/compatible-mode/v1'
$env:AGENT_ENABLED='false'
.venv/Scripts/python.exe -m pytest backend/tests/test_incident_scenarios.py -q
```

付费代表案例通过 `RUN_BAILIAN_INCIDENTS=1` 显式启用，使用北京qwen-plus、每例最多3次调用、2048输出token及0.1元本地预算上限，正常回归默认跳过。原累计10元预算继续包含此前联调。测试跨schema汇总费用仅为本地估算，不能替代账号硬限额或供应商账单；超时/用量未知继续保守预留。

付费案例报告保存至功能跟踪目录的live子目录，包含脱敏证据、来源覆盖、模型产物、调用次数与费用。人工评审必须检查证据引用、观测/假设区分、关键矛盾、缺口、范围及只读建议；JSON合法或测试绿色不等于模型每句话均正确。保留首次失败报告，不能重跑挑选好答案后冒称可靠。

首次真实调用出现了把100/100连接占用直接确认成根因、把配置缺失直接解释为504原因以及提出修改配置的情况；原报告完整保留。后续验收验证上述服务端约束，不能将约束后的文字归功于模型原始语义。具体结果和费用见[验收报告](../.scratch/simulated-incident-scenarios/validation.md)。
